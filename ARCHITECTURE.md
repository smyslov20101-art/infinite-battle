# Архитектура `Infinite Battle`

Документ описывает ключевые архитектурные решения и истории багов, которые сформировали текущую кодовую базу.

---

## 🗄️ Сохранения

### Единый источник правды

Всё игровое состояние живёт в одном объекте — `global.permanent_save`. Раньше параллельно существовали три глобала-дубликата (`global.shop_cards_data`, `global.spin_cooldown_data`, `global.ad_data`), которые синхронизировались разными частями кода. Это давало баги «обновил витрину магазина — кулдаун рулетки сбросился».

**После рефакторинга** дубликаты выпилены, везде идёт обращение к `global.permanent_save.shop_cards_data`, `global.permanent_save.spin_data`, и т.д.

```gml
global.permanent_save = {
    player_name, genes, deck, heroes, crystals, player_stats,
    shop_cards_data:  { cards, auto_refresh_at, ad_charges, ad_reset_day },
    chests_data:      { bought, auto_refresh_at, ad_charges, ad_reset_day },
    spin_data:        { free_spin_at, ad_charges, ad_reset_day },
    wave_rewards_data: { genes, crystals, chests },
    rating_data:      { players, last_update },
    daily_quests:     { last_reset_time, quest_list }
}
```

### Атомарная запись с backup

`save_permanent_to_file()` пишет так:

1. Сериализует в `save_game.sav.tmp`
2. Текущий `save_game.sav` → `save_game.sav.bak`
3. `save_game.sav.tmp` → `save_game.sav`

На любом шаге **минимум один валидный файл существует**. Если игра упадёт в момент записи — следующий запуск возьмёт `.bak` и не потеряет прогресс. При загрузке: основной → если не парсится, `.bak` → если и он битый, дефолт.

### Sync runtime ↔ permanent

Runtime-глобалы (`global.crystals`, `global.genes`, и т.д.) — это «горячая копия» из `permanent_save` для быстрого чтения в кадре.

- `sync_session_from_permanent()` — после загрузки копирует значения в runtime-глобалы
- `sync_runtime_to_permanent()` — вызывается **внутри** `save_permanent_to_file()`, забирает свежие runtime-значения **перед** записью. Невозможно «забыть синкнуть».

## ⏰ Время — только Unix-timestamps

**Не использовать `current_time / 1000` для игровых таймеров.** `current_time` возвращает session-local миллисекунды — обнуляется при перезапуске игры. Был баг «таймер магазина показывает 20 сек, через минуту показывает 38 сек».

Хелперы в `scr_get_unix_timestamp.gml`:

| Функция | Что |
|---|---|
| `scr_get_unix_timestamp()` | Секунды с 1970-01-01 UTC. Идёт даже когда игра закрыта. |
| `scr_get_day_number()` | Номер календарного дня по МСК (UTC+3). Для сброса ежедневных лимитов в полночь. |
| `scr_format_time(seconds)` | `H:MM:SS` или `MM:SS` если меньше часа. |

**Опорная точка для дат — 2000-01-01.** Не использовать `date_create_datetime(1970, 1, 1, ...)` — GameMaker бросает «invalid date conversion» на этой границе (баг движка, не нашёл документации).

## 🛒 Магазин: рулетка / карты / сундуки

Унифицированная логика в `obj_shop_controller`:

| Что | Авто-обновление | Заряды рекламы | Сброс зарядов |
|---|---|---|---|
| 🎰 Рулетка | 1 крут каждые 3 ч | 3/день | в полночь МСК |
| 🃏 Карты | новый набор каждые 24 ч | 3/день | в полночь МСК |
| 📦 Сундуки | новый набор каждые 24 ч | 3/день | в полночь МСК |

Константы: `SPIN_FREE_COOLDOWN`, `SHOP_AUTO_REFRESH`, `CHEST_AUTO_REFRESH`, `AD_CHARGES_MAX`.

## 🔒 `DEBUG_BUILD` — макрос для release-сборки

```gml
#macro DEBUG_BUILD true   // dev: читы работают, LOG/LOG_CAT печатают
#macro DEBUG_BUILD false  // release: код вызовов выпиливается компилятором
```

Все чит-клавиши (`M` +1000 монет, `B` босс, `G` +гены, `C` +кристаллы, `R` reset, и т.д.) обёрнуты в `if (DEBUG_BUILD)`. В release-сборке весь блок становится `if (false) ...` и компилятор GameMaker **полностью выпиливает** его — нет ни кода, ни кнопок-зомби.

### Логирование через макросы

```gml
LOG("Кристаллы: " + string(global.crystals));            // вместо show_debug_message
LOG_CAT("Урон по врагу: " + string(dmg), "combat");      // вместо debug_log(..., "combat")
```

В release: `if (false) show_debug_message(...)` → компилятор выпиливает целиком. Самое важное — выпиливается **склейка строк** (`+ string(...) + ...`), которая иначе жгла бы CPU на каждом кадре. ~1000 старых вызовов `show_debug_message`/`debug_log` массово заменены.

## ⬅️ Кнопка «Назад» — `IS_BACK_PRESSED`

Единая абстракция в `scr_debug.gml`:

```gml
if (IS_BACK_PRESSED) {
    // закрыть попап / уйти назад
}
```

Ловит:
- `vk_escape` (ПК-клавиатура)
- **Автоматически** аппаратная кнопка «Назад» на Android — GameMaker маппит её на `vk_escape` сам
- `mb_right` (правый клик мышью — удобно при разработке)

⚠️ **`vk_back` НЕ существует в GameMaker.** Был добавлен по ошибке, крашил билд. Маппинг на Android делается через `vk_escape`, отдельной константы нет (этого нет в официальной доке, нашёл методом тыка).

На iOS аппаратной кнопки «Назад» нет — там при сборке добавлять on-screen back button (отдельная задача в бэклоге).

## ⚔️ Class-эффекты — `scr_apply_class_onhit`

**Баг был:** dark_blade мечника теней и метки/головокружение паладина почти никогда не срабатывали. Эффекты были прописаны только в `scr_hero_state_fighting`, а герой ближнего боя бьёт **чаще из `STATE_IDLE`** (стоит на позиции и стреляет/рубит), а в `STATE_FIGHTING` бывает лишь короткий момент пока идёт к врагу.

**Решение:** все классовые on-hit эффекты вынесены в `scr_apply_class_onhit(_attacker, _target)`. Эта функция вызывается **И из `scr_hero_state_fighting`, И из `scr_hero_state_idle`** после нанесения урона. Новые классовые эффекты добавляются туда через `if (hero_type == "X")`.

Бонус: дедуп state-скриптов. Раньше каждый из 20 классов героев имел свои `_idle`, `_fighting`, `_moving`, `_dying` скрипты — большая часть кода дублировалась. Сделан общий generic state, классовые отличия только в `scr_apply_class_onhit` и базовых параметрах. Удалено 5 мёртвых скриптов.

## ⚠️ Грабли, на которые наступал

1. **`save_permanent_to_file()` в Step Event каждый кадр.** Был баг с 60 сохранений в секунду — убивал SSD и батарею. Лечится явным вызовом по событию (купил героя, закрыл экран, и т.д.), не из Step.

2. **`global.crystals = 0` в Create-эвенте объекта.** `obj_data_loader.Create` уже загрузил кристаллы из save'а, а другой Create затирал ноль. Лечится через `init_*()` функции, которые ставят дефолт только если значение отсутствует.

3. **Порядок Create-эвентов в `room_splash`:** сначала `obj_data_loader`, потом `obj_persistent_controller`. Если переставить — `persistent_controller` рассчитывает что save уже загружен и крашится. Документировано в комментариях к комнате.

4. **Тень переменной (`var`) с instance-переменной того же имени.** Внутри функции `var detail_hero_id = -1;` → ниже `detail_hero_id = detail_hero_id;` присваивает **локальную самой себе**, а не instance. Был баг в `obj_deck_controller.Step_0` — кнопка «убрать из отряда» не работала. Лечится через `self.detail_hero_id = ...` или просто не объявлять локальную с тем же именем.

5. **Top-level код в скриптах.** В `scr_hero_manager.gml` строки типа `global.crystals = 0` выполняются **один раз при старте игры до загрузки комнат**. Не путать с `init_hero_manager()` — это уже функция, вызывается явно. Top-level код в скриптах = «глобальный сетап», его легко не заметить.

6. **Опечатки в именах ресурсов.** GameMaker не подсвечивает опечатки в `sprite_get_index("spr_shit")` если такой спрайт реально есть с этим именем — ругается только если ресурса нет вообще. Переименовано: `spr_shit→spr_shield_icon`, `bakgroung→background`, `profil→profile`, `zadan→quests`, `warior→warrior`, `arhimage→archmage` и др. — 10 опечаток, иначе блокировало бы ревью в сторах.

## ✅ Что сделано (рефакторинг и аудит)

- Сохранения: атомарная запись, backup, try/catch, миграция со старого формата
- Daily quests: баг с потерей при загрузке исправлен
- Таймеры магазина/рулетки/сундуков: переписаны на Unix-time
- Формат таймеров: `H:MM:SS`/`MM:SS`
- Кнопка «Обновить за рекламу» у сундуков
- Сброс зарядов рекламы в полночь по МСК
- Чит-клавиши обёрнуты в `DEBUG_BUILD`
- Удалён дубликат `G`-чита в `obj_room_controller`
- Переименованы 10 опечаток в именах ресурсов
- Колода: замена героев работает с подсветкой подходящих слотов, кнопка «убрать из отряда» починена (тень переменной)
- Логирование: ~1000 вызовов обёрнуты в `LOG`/`LOG_CAT`
- Кнопка «Назад» унифицирована через `IS_BACK_PRESSED`
- Дедуп state-скриптов героев (Level 1+2: archer/tank moving, berserker/shadow_blade полностью на generic; ярость берсерка восстановлена)
- Same-class замена в `add_hero_to_deck`, parent=null у `obj_shadow_blade`, click-leak при входе в комнату
- Class-эффекты вынесены в `scr_apply_class_onhit`

## ⏳ Бэклог (по убыванию приоритета)

1. **Оставшиеся опечатки в именах ресурсов** (5 мин, но блокирует ревью в сторах).
2. **641 `show_debug_message`** — нужно обернуть в `LOG`/`LOG_CAT` (производительность в release).
3. **Android/iOS конфиги** — без них вообще не собрать APK.
4. **Touch/back-button на iOS** — заменить `vk_escape` и `mouse_wheel_*` на сенсорные эквиваленты + on-screen back button.
5. **Полный рефакторинг state-скриптов героев** — ~20 классов × 3-4 файла → один обобщённый. Большая работа, отложена пока не подтверждены все классовые механики.
